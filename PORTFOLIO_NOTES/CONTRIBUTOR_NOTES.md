# Contributor Notes — DSPy Fork

This is a fork of stanfordnlp/dspy. Keep upstream guidance authoritative.

1. Read the upstream README, CONTRIBUTING.md, licence and current issue/PR history.
2. For local portfolio work, use a clearly separated example or benchmark path.
3. For upstream bugs, reproduce on a clean environment and open a focused patch that follows upstream conventions.
4. Include tests, expected behavior, package versions and benchmark details.
5. Preserve API compatibility and avoid unrelated refactors.
6. Keep local experiments and upstream contributions separately attributed.
7. Never claim an upstream contribution was accepted until the upstream PR is merged.
